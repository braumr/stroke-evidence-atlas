You are building a complete local Python project inside the current empty directory.
Project name:
Stroke Evidence Atlas
Purpose:
Build Version 1 of a local research synthesis engine for stroke rehabilitation, brain injury recovery, and neuroplasticity evidence.
This project should retrieve approximately 2,000 PubMed papers, extract structured rehabilitation evidence using GPT-4o mini, store everything locally in SQLite, score interventions using a transparent configurable framework, and provide a simple Streamlit multipage dashboard for exploration.
This is Version 1.
Do not overengineer it.
Prioritize:
	•	scientific usefulness
	•	clarity
	•	reliability
	•	low cost
	•	maintainability
	•	resumability
	•	readable modular code
Avoid:
	•	unnecessary frameworks
	•	premature optimization
	•	complex abstractions
	•	knowledge graphs
	•	vector databases
	•	conversational agents
	•	Markdown report generation
	•	multi-source literature collection in V1
The code should be modular enough that future collectors and features can be added later, but Version 1 should only implement what is required.
Important clinical caution:
This system summarizes research literature. It must not present itself as medical advice, a treatment plan, or a replacement for clinicians. It may summarize evidence, compare interventions, show uncertainty, and identify research gaps. It must distinguish clinical evidence from mechanistic, animal, weak, or emerging evidence.

============================================================ CHECKPOINTING AND RESUME
Checkpoint after every successfully processed paper.
Collection:
	•	Deduplicate only by exact PMID.
	•	Do not remove papers because they study the same intervention.
	•	Multiple papers on the same intervention are expected and desired.
	•	Store papers as they are collected.
	•	Insert or ignore existing PMIDs.
	•	Create or update extraction_status for each paper.
Extraction:
	•	Before extracting, check extraction_status.
	•	Skip already extracted papers unless --force is used.
	•	Skip papers without abstracts and mark skipped_no_abstract.
	•	If extraction succeeds, write to study_extractions immediately.
	•	Then update extraction_status to extracted.
	•	If extraction fails, update attempts and last_error.
	•	A crash must not require restarting from the beginning.
Scoring:
	•	Scoring should be rerunnable without recollecting papers or re-extracting abstracts.
	•	Aggregation should be rerunnable.

Use GPT-4o mini.

Requirements:
	•	Initialize the OpenAI client using OPENAI_API_KEY.
	•	Show a clear error if OPENAI_API_KEY is missing.
	•	Do not expose API keys in logs.
	•	Use retry with exponential backoff for temporary failures.
	•	Keep cost low.
	•	Do not perform multiple LLM passes on every paper.
Extraction process:
	1	Extract once.
	2	Validate JSON locally.
	3	If JSON validates, save immediately.
	4	If JSON fails validation, run one repair prompt for that paper only.
	5	If repair fails, mark paper as failed.
Use strict JSON output.
Do not infer details not present in the abstract.

	•	unknown
	•	null
	•	empty list
Do not treat animal or mechanistic evidence as human clinical proof.
Do not force an abstract into a rehab intervention if it is actually about diagnosis, epidemiology, biomarkers, or protocol design.

============================================================ SCORING
Create src/scoring.py.
Keep scoring transparent and configurable.
Do not create opaque hardcoded scoring logic.
Use components:
	1	Neuroplasticity Potential
Meaning: How strongly the intervention appears to engage plausible recovery mechanisms.
Consider:
	•	repetition
	•	intensity
	•	task specificity
	•	salience/motivation
	•	motor learning
	•	sensory feedback
	•	cortical reorganization
	•	interhemispheric balance
	•	cardiovascular fitness
	•	sleep consolidation
	•	inflammation modulation
	2	Clinical Evidence Strength
Meaning: Strength of human clinical evidence.
Consider study type:
	•	Meta-analysis
	•	Systematic Review
	•	Randomized Controlled Trial
	•	Cohort Study
	•	Case Series
	•	Case Report
	•	Animal Study
	•	Narrative Review
Suggested direction:
	•	meta-analysis/systematic review of human clinical studies: high
	•	RCT: high
	•	controlled cohort: moderate
	•	pilot/feasibility: low to moderate
	•	case series/case report: low
	•	animal/mechanistic only: low clinical evidence
	•	narrative review: moderate or low depending on content
	•	protocol only: very low
	3	Safety
Meaning: How safe/tolerable the intervention appears based on reported adverse events and general intervention type.
If safety is not reported, use a cautious middle score and note uncertainty.
	4	Practicality
Meaning: How feasible the intervention may be in real-world rehab/home/outpatient settings.
Consider:
	•	equipment burden
	•	specialist supervision
	•	cost
	•	training requirements
	•	home feasibility
	•	caregiver burden
Overall score:
Use configurable weights in src/config.py.
Default weights:
	•	neuroplasticity_potential: 0.40
	•	clinical_evidence_strength: 0.35
	•	safety_score: 0.15
	•	practicality_score: 0.10
Neuroplasticity should remain the dominant weighting, but all weights must be configurable.
Store all component scores and scoring notes.
Evidence tiers:
Assign intervention-level evidence tiers during aggregation:
	•	Strong clinical evidence
	•	Moderate clinical evidence
	•	Emerging evidence
	•	Mechanistic/preclinical only
	•	Insufficient evidence
	•	Conflicting evidence
Do not present the score as proof.
UI should show that scoring is a research synthesis aid, not medical truth.
